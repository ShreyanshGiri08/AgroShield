# AgroShield Database Architecture & Setup Guide

This document describes the relational, temporal, and vector database architecture for **AgroShield**, an AI-powered hyperlocal agricultural intelligence platform.

---

## 1. Prerequisites

- **PostgreSQL 14+** (Recommended: PostgreSQL 15 or 16)
- **pgvector** extension installed.
  - Compatible with managed databases:
    - [Supabase](https://supabase.com/) (pgvector pre-installed; free tier available)
    - [Neon.tech](https://neon.tech/) (pgvector pre-installed; free tier available)
    - [Aiven](https://aiven.io/) (pgvector supported)
    - Local PostgreSQL with `pgvector` compiled or package installed (`postgresql-16-pgvector`)

---

## 2. Extensions Used

1. **`uuid-ossp`**: Generates robust, collision-resistant UUIDv4 primary keys for distributed and microservice-friendly entities.
2. **`pg_trgm`**: Trigram matching for fast fuzzy search across crop names, mandi markets, and document text.
3. **`vector`**: Stores 384-dimensional dense vectors generated by Sentence Transformers (`all-MiniLM-L6-v2`) and powers cosine similarity search via HNSW indexing.

---

## 3. Schema Structure (Module Breakdown)

The schema in `database/schema.sql` comprises 8 functional modules:

1. **User & Farm Management**
   - `users`: Core account details, phone number, language preference.
   - `farmer_profiles`: Geographic location (lat/lon, state, district, village).
   - `farms`: Distinct farm holdings (acres, soil type, irrigation source).
   - `crop_catalog`: Official Indian crop master data (Cotton, Wheat, Soybean, etc.).
   - `crop_growth_stages`: Phenological stages with days-after-sowing offsets.
   - `farm_crops`: Active cultivation records tied to specific farm plots.

2. **Data Source Registry & External Intelligence**
   - `data_source_registry`: Full data provenance tracking for all APIs and sources.
   - `weather_observations`: Real-time weather data fetched from Open-Meteo.
   - `weather_forecasts`: 7-day weather forecasts with precipitation probabilities.
   - `mandi_markets`: Official AGMARKNET / data.gov.in market catalog.
   - `mandi_prices`: Real-time commodity arrivals and modal prices.

3. **Agricultural RAG & Knowledge Base**
   - `agricultural_documents`: ICAR / Agricultural University research papers and bulletins.
   - `agricultural_document_chunks`: Extracted text passages tagged by crop, stage, and topic.
   - `document_embeddings`: 384-dim dense vector embeddings with HNSW indexing (`vector_cosine_ops`).

4. **Agentic AI & Execution Telemetry**
   - `conversations` & `conversation_messages`: Multi-turn farmer dialogues.
   - `agent_runs`: Audit records of agent execution sessions.
   - `agent_execution_steps`: Transparent execution steps shown to the farmer in real time.
   - `tool_execution_logs`: Exact input/output payloads, latencies, and tool health.

5. **Deterministic Crop Risk & Advisories**
   - `risk_rule_definitions`: Agronomic threshold rules (e.g. Cotton flowering + rain > 35mm).
   - `crop_risk_assessments`: Deterministic Python engine evaluations (Score: 0-100, Level: LOW/MODERATE/HIGH/SEVERE).
   - `advisories`: Structured guidance with actionable checklists.
   - `advisory_citations`: Strict provenance linking advisories back to specific RAG text chunks.
   - `scenario_analyses`: Counterfactual what-if calculations.

6. **Multimodal AI & Voice**
   - `crop_images`: Metadata for plant health images.
   - `image_analysis_results`: Symptoms, potential causes, and legal uncertainty disclaimers.
   - `voice_interaction_metadata`: Audio query durations and WebSpeech transcription metrics.

7. **Farmer Memory & Proactive Alerts**
   - `farmer_memory`: Learned preferences and historical farm occurrences.
   - `farmer_feedback`: 1-5 star ratings and usefulness tags.
   - `alerts`: Scheduled proactive notifications for impending risks.
   - `notification_preferences`: Per-farmer alerting options.

8. **Operations & Reference Seeding**
   - `api_request_logs`: Outbound API telemetry.
   - `scheduled_job_runs`: Telemetry for background cron tasks.
   - Seeded agronomic rules and crop catalogs (ICAR-backed, **zero mock user data**).

## 4. Execution Instructions

### Option A: Using `psql` (CLI)
```bash
# Connect to your PostgreSQL database
psql "postgresql://<user>:<password>@<host>:<port>/<dbname>?sslmode=require" -f database/schema.sql
```

### Option B: Using DBeaver, pgAdmin, or Supabase SQL Editor
1. Open your database management tool or web console.
2. Ensure you have rights to create extensions (`CREATE EXTENSION`).
3. Copy the entire contents of `database/schema.sql`.
4. Run the script.
5. Verify execution by running:
   ```sql
   SELECT table_name FROM information_schema.tables WHERE table_schema = 'public';
   ```

## 5. Verification Checklist

Run this quick test query after running the script:
```sql
SELECT 
    (SELECT COUNT(*) FROM crop_catalog) as crops_seeded,
    (SELECT COUNT(*) FROM crop_growth_stages) as stages_seeded,
    (SELECT COUNT(*) FROM risk_rule_definitions) as risk_rules_seeded,
    (SELECT COUNT(*) FROM data_source_registry) as sources_seeded;
```

Expected output:
- `crops_seeded`: >= 7
- `stages_seeded`: >= 10
- `risk_rules_seeded`: >= 3
- `sources_seeded`: >= 4
